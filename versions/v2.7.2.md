# @meng-xi/uni-router v2.7.2 更新：修复 H5 端浏览器后退无响应

> v2.7.2 为修复版本，解决 H5 端「通过非 `#/` 地址进入应用后，在二级页面点击浏览器后退没有任何反应」的问题（issue #43）。问题源于 `h5BackUrl` 记录时机过早，叠加「撤销后退 + 重放 `navigateBack`」与 uni-app 异步 popstate 切页的竞态。本版本改为**直接守卫浏览器已完成的后退**，仅守卫中止时才恢复原页面，且完全向后兼容。

## 前言

- **App 端**：`onBeforeBack` 通过全局 mixin 的 `onBackPress` 接入物理返回键 / 导航栏返回 / `navigateBack`，不受本次改动影响。
- **H5 端**：`onBeforeBack` 通过浏览器 `popstate` 事件接入后退。v2.7.1 为修复死循环（issue #39）引入了「撤销后退 → 守卫放行后重放 `navigateBack`」策略，该策略在页面栈时序变化时仍会失败。v2.7.2 直接移除该策略。

v2.7.2 不改动 public API 与守卫语义，仅重构 H5 返回守卫的执行方式。

---

## 一、问题现象与影响（issue #43）

H5 端通过站点根路径（如 `http://localhost:5173`，而非 `http://localhost:5173/#/`）进入应用后，按 **首页 → 二级页** 导航，再点击浏览器后退按钮：

- URL 与页面**均停留在二级页**，后退没有任何反应
- 控制台无 JS 报错

同样操作若从 `http://localhost:5173/#/` 进入则表现正常，说明问题与 `install` 阶段记录的地址基准有关。

复现环境：uni-app H5（Vue 3 + Vite）、`@meng-xi/uni-router 2.7.1`。

---

## 二、根因

### 1. `h5BackUrl` 记录时机过早

`install()` 中记录 `location.href` 作为「当前页 URL」基准，此时 uni-app 尚未把地址规范化为 `#/`，实际记录的是 `http://localhost:5173/`。浏览器后退到 `#/` 时 URL 与基准不一致，`handleH5PopState` 误判为「外部后退」，进入「撤销 + 重放」分支。

### 2. 撤销与重放存在竞态

原实现收到 popstate 后：

```
1. history.go(1)           // 撤销此次后退（异步任务）
2. 运行返回守卫链           // onBeforeBack → beforeEach → beforeResolve
3. 守卫放行 → executeBack  // uni.navigateBack 重新后退
```

守卫链（尤其是无耗时守卫时）会在微任务内走完，而 uni-app（vue-router）对 popstate 的切页提交是异步的。等到 `uni.navigateBack` 重放时，uni-app 已把页面栈弹到首页，`navigateBack` 失败（异常被守卫链的 `catch` 静默吞掉）；随后挂起的 `history.go(1)` 生效，把 URL / 页面又推回二级页——净效果就是「后退无效」。

对应控制台日志：

```
[onBeforeBack] 从 /pages/detail/detail 返回到 /pages/index/index
[beforeEach]  从 /pages/detail/detail -> /pages/index/index
[afterEach]   导航完成: /pages/detail/detail -> /pages/index/index
[onRouteChange] 路由变化: /pages/index/index -> /pages/detail/detail   ← 被撤销后的重放推回二级页
[detail onLoad] ...
```

---

## 三、修复方案

改动集中在 `router/back-guard.ts` 与 `router/index.ts`，不涉及 public API。

### 1. 守卫浏览器「已完成」的后退

`popstate` 触发时浏览器**已经完成后退**，因此不再撤销，而是：

- 通过 `getH5LocationPath()` 从地址栏解析后退目标（hash 模式取 `#/...`，history 模式取 `pathname`；根路径 `'/'` 映射到页面栈首屏；`resolve` 失败则放行浏览器默认行为）
- 守卫放行后**不做任何额外操作**，由 uni-app 自行完成切页，目标页 `onShow` 时全局 mixin 自动 `syncRoute`
- 仅有守卫中止时，才用 `history.go(1)` 恢复原页面

```typescript
handleH5PopState(): void {
  // ... 自身导航放行分支（h5ReturningBack / backGuardRunning / h5GuardRunning）

  const from = this.deps.getCurrentRoute()
  const to = this.resolveH5BackTarget()
  this.h5BackUrl = location.href

  if (!to || to.fullPath === from.fullPath) return

  this.h5GuardRunning = true
  this.runBackGuardChain(to, from, async () => {}, () => this.restoreH5Back(from.path))
    .finally(() => {
      this.h5GuardRunning = false
    })
}
```

### 2. 基准 URL 同步 `syncH5BackUrl()`

原 `setH5BackUrl(url)` 改为 `syncH5BackUrl()`（内部读取 `location.href`），并在 **install** 与**每次导航成功后**同步，消除过期基准导致的误判。

### 3. 中止回滚与并发保护

- `runBackGuardChain` 新增 `onAbort` 回调：守卫中止时调用 `restoreH5Back()`，置位 `beginH5Back` 标记后 `history.go(1)` 前进回原页面，恢复产生的 popstate 不会被误判为新的外部后退
- 新增 `h5GuardRunning` 并发标记，避免守卫链执行期间重复 popstate 重复执行守卫链
- 守卫放行后的 `syncCurrentRoute()` 增加页面栈判断：仅当页面栈已到达目标页时才强制同步，避免把 `currentRoute` 回滚到来源页

## 四、修复效果与回归验证

在 playground H5 环境回归，覆盖 issue 描述场景与守卫中止场景：

| 场景                                            | 修复前                     | 修复后                                  |
| ----------------------------------------------- | -------------------------- | --------------------------------------- |
| 非 `#/` 入口：首页 → 二级页 → 浏览器后退         | 停留在二级页，后退无效     | 正常回到首页 ✅                         |
| `#/` 入口：首页 → 二级页 → 浏览器后退           | 能返回，但不触发 `onBeforeBack` | 正常回到首页，且完整触发守卫链 ✅  |
| 三级页面：详情 → 导航 → 首页，连续两次浏览器后退 | 正常                       | 逐级正确返回 ✅                         |
| `onBeforeRouteLeave` 阻止 + 浏览器后退           | —                          | 停留当前页，`onError` 导航被守卫中止 ✅ |
| 取消阻止后再次浏览器后退                        | —                          | 正常返回 ✅                             |
| 详情页「返回上一页」（`router.back()`）         | 正常                       | 正常 ✅                                 |

守卫链日志顺序：`onBeforeBack → beforeEach → beforeResolve → afterEach`，无重复的 `onRouteChange` 回滚。

## 五、升级指南

v2.7.2 为 **PATCH** 版本，完全向后兼容，无破坏性变更：

- 未改动任何公开 API 签名、选项、守卫返回值约定
- 修复仅影响 H5 浏览器后退（popstate）路径；`router.back()` / App 返回 / `push` / `replace` / `relaunch` 行为不变
- 此前从 `#/` 入口后退不会触发 `onBeforeBack`，本版本统一触发守卫链（与文档描述一致）
- 建议升级后重新验证 H5 平台的浏览器后退（尤其从站点根路径直接进入、以及存在 `onBeforeBack` / `onBeforeRouteLeave` 守卫时）
- uni_modules 用户直接替换 `mxuni-router-v2` 目录即可，`js_sdk` 产物已同步
